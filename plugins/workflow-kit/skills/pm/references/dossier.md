# Dossier

The dossier is the source of truth for one repository and its project manager. It lives in the project's Obsidian vault.

## Layout

```text
<vault>/Features/
  _project/board.md         GENERATED by dossier.py board --project; never hand-edited
  _project/inbox.md         GENERATED by scan.py scan; never hand-edited
  _project/ignored.md       append-only, ignored discovery keys
  _project/items/<slug>.md  standalone work items
  _project/log.md           append-only, project manager and standalone events
  _project/decisions.md     append-only, project-wide
  <feature>/brief.md         goal, constraints, architecture, non-goals
  <feature>/decisions.md     append-only, feature
  <feature>/log.md           append-only, one short entry per session
  <feature>/board.md         GENERATED by dossier.py board; never hand-edited
  <feature>/items/<slug>.md  one file per work item (frontmatter + notes)
  <feature>/designs/         stage 2 design notes
  <feature>/plans/           stage 3 handoff plans
<vault>/.gitattributes       contains `decisions.md merge=union`, `log.md merge=union`,
                            and `ignored.md merge=union`
```

There is no escalation file.

## File templates

`brief.md` has these headings:

```markdown
# <feature>

## Goal

## Constraints

## Architecture

## Non-goals
```

Each `decisions.md` entry is one append-only line:

```text
- <date> [<scope>] <decision> — <why> (<source>)
```

`<source>` is, for example, `design review`, `PR #52 unplanned`, or `user reversal`.

## Item format

Item frontmatter is a restricted YAML subset parsed and written without a YAML dependency.
The supported forms are `key: scalar`, `key: [a, b]`, and an empty value. The body after the
closing `---` is free-form Markdown.

| Key | Values |
|---|---|
| `slug`, `title` | text |
| `stage` | `idea` · `design` · `plan` · `implement` · `pr` · `review` · `merged` · `done` · `dropped` |
| `status` | `none` · `queued` · `blocked` · `running` · `paused` · `stuck` · `idle` |
| `origin` | `implement-plan` · `external` (a PR that was not opened by implement-plan) |
| `worker`, `sessionId`, `workerKind` | session name, id, and `plan`·`implement`·`ci`·`sync`·`comments` |
| `worktree`, `branch`, `pr`, `plan`, `design` | paths, branch, PR number, and vault-relative links |
| `blockedBy` | list of `<slug>` or `<feature>/<slug>` |
| `files`, `modules` | lists, from the plan |
| `notified` | list of event keys already sent, for example `pr-ready`, `fix-pushed-2` |
| `round`, `reviewSeen` | review-round counter, ISO time of the last review handled |
| `question` | one-line `Question:` from a stuck worker's `needs input` block, while `status: paused` |
| `unplanned` | count of `### Unplanned Decisions` items in the PR body; `0` for none |
| `updated` | ISO time, set on every write |

## Worker names

A worker is named `<feature>-<slug>`, plus `-<workerKind>` for every kind except
`implement`. Examples are `kmp-ktor` and `kmp-ktor-ci`. Notifications use the same name in
`claude attach <name>`.
Standalone items use the `project` label: `project-<slug>[-<workerKind>]`,
`blockedBy: [project/<slug>]`, and notifications prefixed with `[project]`.
`herdr.py` lowercases the worker name, replaces characters outside `[a-z0-9_-]` with
`-`, ensures it starts with a letter, and caps it at 32 characters. Long names keep the
last hyphen-separated part (the kind suffix when there is one) when it is 23 characters
or fewer, and get a 6-character stable hash. The tab label is the item title.

## Events

Every notification is one line under 200 characters and starts with `[<feature>]`.

Notify for: `plan-done`, `impl-started`, `pr-ready`, `fix-pushed-<round>`, `paused-<id>` (a
worker's `needs input`), `decision-<n>` (a project manager ask), `stuck`, and `quota-blocked`.

Log only in `log.md`, without a notification: `phase-done`, `ci-fixed`, `synced`, and
`retro-ready`.

## Command contract

Every successful command writes exactly one JSON object to stdout and exits 0. For
`dossier.py`, invalid usage, unknown item keys, and invalid stages or statuses write an error
to stderr and exit 2.
`herdr.py` also uses stderr and exit 2 for usage errors (including malformed items or a
missing worker for attach); mirror runtime failures return JSON `warning` with exit 0.

- `resolve-vault [--project-dir D]` → `{vault, source, featuresDir}`. `source` is `config`,
  `convention`, or `none`.
- `config [--project-dir D]` → `{maxWorkers, vault, herdr}`. `herdr` is a boolean from
  `pm.herdr`, default `true`; a non-boolean falls back to `true` and adds
  `warnings: ["pm.herdr must be a boolean; using true"]`, with exit 0. The `warnings`
  key is absent when there is no warning.
- `list --vault V [--match NAME]` → `{features, project}`, plus `match` and `closest`
  when matching. Each feature has `name`, total `items`, and `stages` counts; `project` has
  `{items, stages}` for `_project/items/`, which is excluded from `features`. `match` echoes
  the query; check `features` for an exact name.
- `init --vault V --feature F` → `{ok, featureDir, created}`. Rejects `project` and
  `_project` as feature names and also initializes project files.
- `init-project --vault V` → `{ok, projectDir, created}`. Idempotently creates
  `_project/items/`, `_project/log.md`, `_project/decisions.md`, and union attributes.
  `created` lists newly written template files; it does not list directories or attributes.
- `item new --feature-dir D --slug S --title T [--set k=v]...`, `item get <file>`, and
  `item set <file> k=v... [--add k=v] [--note TEXT]` → `{file, item, body}`. `--set` may be
  repeated for `item new`; `--add` may be repeated for `item set`.
- `board --feature-dir D` → `{ok, board, changed, items}`. It emits a table for every stage,
  in the stage order documented above, with Item, Status, PR, Worker, and Updated columns.
- `board --project --vault V` → `{ok, board, changed, items, warnings}`. Writes
  `Features/_project/board.md`: per-label active/done counts, stage tables excluding `done`
  and `dropped`, and the generated inbox. Active means neither `done` nor `dropped`;
  `items` counts valid items, including completed and dropped ones; `warnings` lists skipped
  malformed items. Item cells use `[[Features/<dir>/items/<slug>\|<slug>]]`. `--project` and
  `--feature-dir` are mutually exclusive.
- `sync --vault V -m MSG [--board D]... [--] [paths...]` → `{ok, committed, attempts}` on
  success; failure has `ok:false` and either `conflict` or `error`. A rejected push is retried
  up to three total attempts. Any `--board` also regenerates and stages the project board;
  `--board V/Features/_project` requests the project board only. Rebase recovery regenerates
  conflicting boards and keeps the local `_project/inbox.md`; other conflicts abort before
  return.
- `checks [--project-dir D]` → `{allowRule, trusted, permissionMode, fixes}`.

`resolve-vault` and `config` merge the `pm` object from user then project
`.claude/workflow-kit.json`, so project keys override the same user keys. At each config
file, a missing or non-object `pm` falls back to legacy `lead`. Keys are `pm.vault`,
`pm.maxWorkers`, and `pm.herdr`. `checks` adds `rename "lead" to "pm" in <path>` to `fixes`
when a file has `lead` and no `pm`. The vault convention is
`~/Workspace/Obsidian/<lowercased repo directory name>-vault`. `sync` never force-pushes;
only the project manager passes `--board`, while workers never regenerate boards.

The commands above use `dossier.py`. The additional scripts have these contracts:

- `lock.py acquire --project-dir R [--force]` → `{ok, lock, holder, stale, takenOver}`.
  `holder` is null or `{pid, host, cwd, startedAt}`. A live other owner returns `ok: false`
  with its holder; no Claude ancestor adds `reason: "no claude ancestor"`. A stale local
  lock is taken over automatically; a remote-host holder requires `--force`.
- `lock.py release --project-dir R` → `{ok, released}`. Only the owner removes the lock.
- `lock.py status --project-dir R` → `{held, holder, stale}`; never writes. Lock refusals
  return JSON with exit 0; usage errors write stderr and exit 2. `--force` is acquire-only.
- `scan.py scan --vault V --project-dir R [--exclude-session NAME]...` →
  `{ok, entries, warnings, inbox, changed}`. Each entry is
  `{key, title, pr, branch, worktree, session, author, draft}`. It writes generated
  `Features/_project/inbox.md` only when content changes. Source failures become warnings
  with `ok: true` and exit 0; matching considers this vault's items only.
- `scan.py adopt --vault V --project-dir R --key K (--feature F | --standalone) --slug S
  [--title T] [--exclude-session NAME]...` → `{ok, file, item, inbox}`. The target options are mutually exclusive.
  Pass the same supervisor exclusions as `scan`. Rescans, creates an external idle item at `pr` when a PR exists or `implement` otherwise,
  and removes the entry from the inbox. Missing keys and unknown features are usage errors.
- `scan.py ignore --vault V --key K` → `{ok, ignored, inbox}`. Appends the key to
  `_project/ignored.md` and removes it from the generated inbox without rescanning.
  Scan usage/file errors return `{ok: false, error}` with exit 2, rather than stderr.

Follow `references/project.md` § "Discovery and inbox" for user-directed triage and sync,
and `references/project.md` § "Lock" before supervising workers.
